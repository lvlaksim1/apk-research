# v0.20 — Continuous Screen Evidence

## Purpose

v0.20 evaluates whether a project-owned Android-side MediaCodec stream can eventually replace chunked Android `screenrecord` without weakening forensic coverage or the established runtime.

It does not perform that replacement. The new collector runs in parallel and remains experimental.

## Architecture

```
apk-research host
  ├─ Emulator gRPC/MMAP → AndroidView        (live UI, unchanged)
  ├─ adb screenrecord                         (canonical evidence)
  └─ apk-research sidecar control
       └─ second adb reverse media socket
            └─ Surface → MediaCodec AVC
                 └─ packet flags + device PTS + exact bytes
```

The media connection is separate from the sidecar text control channel. Host listeners exist before the Android agent is asked to connect, so readiness does not depend on device-port polling.

## Research ZIP evidence

- `01_raw/screen/continuous-screen.h264`: exact concatenated MediaCodec payload bytes.
- `02_normalized/continuous-screen-packets.jsonl`: packet sequence, MediaCodec flags, PTS, payload size and raw offset.
- `02_normalized/continuous-screen.json`: capture configuration, sidecar handshake, stream header, timing semantics, stop statistics, cleanup and status.
- `02_normalized/screen-ab-comparison.json`: diagnostic comparison with canonical screenrecord.

The packet index is an index over the raw encoded byte artifact. It does not replace it.

## Timing semantics

`presentationTimeUs` is generated by MediaCodec on the Android target and is preserved exactly. v0.20 records this as a device media-presentation clock domain; it is not converted to or described as UTC.

The sidecar stream header separately records `SystemClock.elapsedRealtimeNanos()` at stream startup. Best-effort ADB UTC samples are recorded at collector boundaries for diagnostics, not used to relabel packet PTS.

## Failure semantics

The collector is `required=false`. If it is unavailable or fails, the failure is recorded in its metadata, but canonical screenrecord/logcat/PCAP evidence may still form a complete Research Session.

This is deliberate: experimental evidence must not be allowed to destroy an established evidence baseline.

## A/B promotion rule

`screen-ab-comparison.json` identifies:
- canonical and experimental backend/status;
- canonical chunk/capture/frame spans;
- experimental packet/frame/byte counts and PTS span;
- presentation-span delta;
- `promotion_decision=not-automatic`.

CI success demonstrates technical operation on the managed AVD only. Canonical promotion requires later real owner-side A/B validation and a separate explicit decision.

## Scope exclusions

v0.20 does not add Audio Evidence and does not add a user-facing Virtual Display research mode.

The hidden Emulator → gRPC/MMAP → AndroidView runtime and persistent gRPC input remain authoritative.
