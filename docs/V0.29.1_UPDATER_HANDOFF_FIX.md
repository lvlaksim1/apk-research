# v0.29.1 — Reliable Self-Update Handoff

## Problem

Owner-side validation showed that update discovery, download and SHA-256 verification completed, the GUI announced a restart and exited, but no installer/restart followed.

The old path delegated the post-exit work to a hidden PowerShell process. Once the GUI exited, any failure in that relay became invisible.

## Fix

The relay is removed.

After a verified download:
1. apk-research constructs Inno Setup arguments;
2. writes a handoff record;
3. directly creates the installer process;
4. only after successful process creation does the GUI exit;
5. Inno Setup updates the same application directory;
6. Inno Setup itself relaunches apk-research after successful completion.

## Logs

The updater stores:
- `%LOCALAPPDATA%\apk-research\updates\handoff.log`;
- `%LOCALAPPDATA%\apk-research\updates\installer.log`.

These survive the application exit and make post-mortem diagnosis possible.

## Acceptance

Windows CI installs public v0.29.0 into a test directory, verifies it, then calls `launch_update_after_exit(..., relaunch=False)` from a short-lived Python process using the newly built v0.29.1 installer. After that process exits, CI waits at least five seconds between checks and requires the installed executable to report v0.29.1.

The acceptance fails with both updater logs printed if the version never changes.

## Boundaries

This release does not alter:
- GitHub release discovery;
- SHA-256 verification;
- same-AppId update semantics;
- APK/XAPK handling;
- emulator runtime;
- evidence capture or interpretation.
