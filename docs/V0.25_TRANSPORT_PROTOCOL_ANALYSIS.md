# v0.25.0 — Transport and Protocol Analysis

v0.25.0 extends the existing Packet Inspector without changing the authoritative evidence hierarchy. The raw `01_raw/network/traffic.pcap` remains the source of truth; the new analysis is a derived, reproducible view over bytes already present in that capture.

## TCP capture analysis

For each selected TCP flow, Packet Inspector now reports capture-bounded observations for sequence numbers, acknowledgments and advertised windows. The report identifies whether a plain SYN and a FIN/RST are present in the selected capture, repeated or overlapping observed sequence ranges, gaps between observed sequence ranges, repeated ACK values and zero-window packets.

These are deliberately named capture observations. A sequence gap does not by itself prove packet loss, a repeated sequence range does not by itself prove a network retransmission, and absence of SYN/FIN/RST does not prove that the event did not occur outside the capture.

## DNS

Complete DNS messages present in selected TCP/UDP packet payloads are decoded into questions and supported resource records. Query/response grouping is emitted only when one selected flow contains one unambiguous query and one unambiguous response with the same transaction identifier. Ambiguous or partial groups remain explicitly marked as such.

## TLS

Complete TLS records that are actually present in captured bytes can expose ClientHello and ServerHello metadata such as SNI, ALPN, supported/selected protocol version and selected cipher suite. The analyzer also performs a bounded contiguous reconstruction of observed TCP payload bytes so a hello split across captured TCP segments can be recognized when the observed sequence is contiguous.

No encrypted application payload is represented as plaintext. Missing records are not synthesized.

## QUIC and HTTP/3

The v0.25 report aggregates the existing passive QUIC evidence: observed version, packet type, Initial metadata, SNI and ALPN. HTTP/3 is reported only when the captured QUIC ClientHello advertises an `h3` ALPN value. QUIC application payload remains encrypted metadata-only evidence.

## Observable HTTP

Cleartext HTTP/1.0 or HTTP/1.1 request/response headers and the cleartext HTTP/2 connection preface are recognized only when the necessary bytes are actually captured. One request/response transaction is grouped only when there is exactly one complete request and exactly one complete response in opposite directions in the selected flow; otherwise no synthetic pairing is created.

## Evidence contract

- Raw PCAP remains authoritative network evidence.
- All analysis is scoped to the selected flow and captured bytes.
- `causal_claim` remains `false`.
- Packet/action relations remain temporal-only.
- Absence from the report means “not observed in this capture”, not “did not occur”.
- Missing traffic, plaintext and causality are never synthesized.
- v0.10.5 startup/clean-launch sequencing and the hidden Emulator → gRPC/MMAP → AndroidView live display path are unchanged.
- Audio Evidence and user-facing Virtual Display remain out of scope.
