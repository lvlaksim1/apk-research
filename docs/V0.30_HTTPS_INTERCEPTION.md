# v0.30 — HTTPS Traffic Inspection

## Goal

Show actual HTTP request/response content for HTTPS traffic generated by the researched Android application when TLS interception succeeds. SNI, TLS metadata or an encrypted PCAP alone do not satisfy this feature.

## Architecture

apk-research launches an isolated mitmproxy worker as a hidden child mode of the same packaged executable. The worker listens only on host loopback.

The managed Android emulator is connected to that worker with `adb reverse` and an explicit Android global HTTP proxy. No listener is exposed to the LAN.

For Android 15, the generated research CA is inserted into the rooted system trust view used by Conscrypt. The implementation mounts a writable certificate view and propagates it into Zygote mount namespaces so newly launched applications inherit the trusted CA.

## Evidence

The collector writes:
- `02_normalized/http-transactions.jsonl` — transaction metadata;
- `02_normalized/http-bodies/` — exact decoded message bodies captured by the proxy;
- `02_normalized/http-interception.json` — proxy/CA/routing provenance;
- `01_raw/network/https-proxy.stderr.txt` — raw proxy diagnostics.

Each transaction records URL, method, HTTP version, headers, status, timing, body metadata and whether TLS content was decrypted.

## UI

The HTTP/HTTPS results viewer provides:
- searchable transaction table;
- host/path/status/protocol columns;
- request headers;
- request body;
- response headers;
- response body;
- formatted JSON/text and bounded hex preview for binary payloads.

## Forensic boundary

The interceptor actively changes the network path. The passive PCAP remains authoritative for packets that actually traversed the Android research environment, but must not be described as if no interception occurred.

The provenance artifact explicitly records the Android proxy, adb-reverse transport and the possibility that QUIC/HTTP3 behavior changes under proxy routing.

## Known boundary

Certificate pinning and application-owned trust stores may reject the research CA. v0.30 does not silently patch applications and does not claim universal HTTPS decryption.

HTTP/3/QUIC decryption is outside the v0.30 acceptance contract.

## Release acceptance

The Android 15 AVD gate builds and installs a real launchable test APK. The APK performs an HTTPS request to `https://example.com/`. Acceptance requires:
- the research session remains healthy;
- the HTTPS collector completes;
- the exported transaction matches the exact URL;
- TLS is marked decrypted;
- response status is 200;
- the response body is non-empty;
- the subsequent full AVD research acceptance still passes.
