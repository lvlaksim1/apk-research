# apk-research — Research Timeline v0.9.1

## Назначение

Research Timeline связывает действия пользователя с событиями Android и сетевой активностью по общей временной шкале. Raw PCAP, logcat, screen recording и lifecycle events остаются первичными evidence.

## Граница записи действий

Начиная с v0.9.1 user actions не принимаются в момент clean-launch transition. Последовательность:

```text
collectors armed
→ clock calibration
→ force-stop (clean mode)
→ launch
→ package_launched
→ user_action_capture_enabled
```

Поэтому startup network/lifecycle activity до фактического запуска target package не приписывается первому пользовательскому действию.

## Clock calibration

Перед запуском target package выполняется серия из 9 коротких Android clock probes через ADB nanosecond clock.

Для каждого probe фиксируются:

- host UTC до запроса;
- monotonic round-trip;
- Android realtime в ns;
- midpoint host timestamp;
- target-minus-host offset.

Для итогового offset используются 5 probes с минимальным round-trip; итог — median offset. Также сохраняется оценка uncertainty = половина median RTT.

Artifact:

```text
02_normalized/clock-calibration.json
```

Если high-resolution calibration недоступна, viewer может использовать сохранённые metadata/session clock markers.

## Adaptive correlation windows

Refined Timeline использует causal-oriented окно:

```text
action end → min(action end + 2 s, next action start)
```

До action больше не добавляется прежний pre-window. Соседние действия не должны получать один и тот же post-action interval.

Каждая correlation содержит:

- фактическую длину окна;
- признак truncation следующим action;
- packet/byte counts;
- flow summaries;
- new flows;
- DNS queries;
- best-effort TLS SNI;
- relevant logcat sample;
- `causal_confidence`;
- список ambiguity reasons.

Пока нет app-specific socket/UID attribution, Timeline явно маркирует correlation как `temporal-only` и `causal_claim=false`.

## GUI

Вкладка «Результаты» показывает Research Timeline в табличном виде: время, тип, событие, network summary и logcat summary.

При открытии архива v0.9.1 refined view детерминированно пересчитывается во временном workspace из evidence самого Research ZIP. Архив не модифицируется при просмотре.

Это позволяет улучшать аналитический слой без переписывания raw evidence и без изменения validated runtime.

## Совместимость Research ZIP

Базовый `02_normalized/research-timeline.json` сохраняется для совместимости формата v0.9.0. v0.9.1 GUI строит refined schema 0.2 при чтении архива, используя дополнительно `clock-calibration.json`.

Следующий этап может сделать refined schema новым canonical derived artifact после отдельной миграции ZIP contract.

## Runtime

Embedded Android runtime не изменён:

```text
-qt-hide-window
→ Emulator gRPC
→ MMAP framebuffer
→ AndroidView
```

Input остаётся persistent gRPC `streamInputEvent`.
