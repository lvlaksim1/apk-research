# Mobile Research v0.1 — Research Session Core

## 1. Назначение

v0.1 должна доказать основной вертикальный сценарий Mobile Research: Windows-программа подключается к Android Research Target, запускает исследуемое приложение, синхронно собирает обязательные исходные данные, корректно завершает сессию и формирует воспроизводимый Research ZIP.

v0.1 не должна решать все задачи исследования Android. Её задача — создать надёжное основание, на которое позже можно добавить MITM, статический анализ APK, корреляцию событий, AVD-PLAY, Physical Device и GUI.

## 2. Reference environment

Для первого end-to-end результата используется:

- host: Windows;
- runtime: Python >= 3.11;
- транспорт управления: ADB;
- target: Android Emulator класса **AVD-RESEARCH**;
- исследуемое приложение: заранее доступный package на target или APK, установленный отдельным шагом;
- raw network capture должен быть технически доступен на выбранном AVD-RESEARCH.

AVD-PLAY и Physical Device являются частью общей архитектуры, но не обязательны для acceptance v0.1.

## 3. Входные данные

Обязательные:

1. ADB target serial.
2. Android package name исследуемого приложения.

Настраиваемые:

- путь к ADB, если он не найден автоматически;
- корневая папка runtime-сессий;
- путь сохранения итогового Research ZIP.

APK-файл не является обязательным входом v0.1: package может быть уже установлен на target.

## 4. Preflight

До активной записи Mobile Research обязана проверить:

1. ADB найден и запускается.
2. Target существует в `adb devices`.
3. Состояние target — `device`, а не `offline` или `unauthorized`.
4. Package установлен.
5. Доступно получение базовых device metadata.
6. Доступны все обязательные collectors v0.1.
7. Доступно создание runtime-каталога и итогового архива.

Если обязательный пункт не выполнен, исследуемое приложение не запускается, а пользователю возвращается точная причина отказа.

## 5. Обязательные collectors v0.1

### 5.1 Android logcat

Сохраняется непрерывный raw-поток logcat за время исследовательской сессии.

Файлы:

- `01_raw/logcat/logcat.txt` — stdout `adb logcat`;
- `01_raw/logcat/logcat.stderr.txt` — stderr процесса;
- `02_normalized/logcat.json` — команда, PID, timestamps, return code, способ остановки и размеры artifacts.

Требования:

- collector стартует только после перехода session в `starting` и до запуска исследуемого package;
- используется доступный поток всех log buffers без package/tag-фильтра;
- timestamps сохраняются в raw log;
- Android log buffer не очищается;
- допускается минимальный pre-roll `-T 1`; фактическая граница capture определяется сохранённым host timestamp;
- stderr/ошибки collector фиксируются отдельно;
- graceful STOP выполняется до принудительного kill;
- forced kill после grace period фиксируется, но не инвалидирует уже записанный evidence;
- неожиданное завершение процесса либо пустой `logcat.txt` делают collector `failed` и session degraded;
- уже записанные raw bytes не удаляются при ошибке.

### 5.2 Screen recording

Экран target записывается последовательными независимыми MP4 chunks.

Файлы:

- `01_raw/screen/screen-NNNN.mp4` — raw video chunks;
- `01_raw/screen/screen-NNNN.screenrecord.txt` — stdout/stderr соответствующего `screenrecord`;
- `02_normalized/screen.json` — хронология chunks, команды, timestamps, return codes, remote PID, forced-kill marker и размеры.

Требования:

- collector стартует в session state `starting`, до запуска исследуемого package;
- стандартная длина chunk v0.1 — 170 секунд, конфигурируемый диапазон 1–180;
- завершившийся по time limit chunk переносится на host до запуска следующего;
- health-check orchestrator должен вызываться регулярно, чтобы минимизировать разрыв между chunks;
- уже перенесённый chunk не удаляется при ошибке следующего;
- STOP сначала пытается адресно завершить известный remote PID `screenrecord` через SIGINT;
- fallback использует host-side terminate и kill только после grace period;
- forced kill фиксируется, но непустой успешно перенесённый MP4 остаётся валидным evidence;
- пустой или неперенесённый chunk делает collector `failed`;
- nonzero return code при естественном завершении chunk считается failure;
- временные remote-файлы после успешного/неуспешного pull удаляются best-effort.

### 5.3 Raw network capture

Обязательна запись сырых сетевых пакетов независимо от будущего MITM.

```text
raw capture = evidence source
MITM/protocol decoder = optional derived source
```

v0.1 не обязана расшифровывать TLS.

Reference backend v0.1: **adb-tcpdump** на AVD-RESEARCH.

Preflight:

- target должен быть emulator/AVD-RESEARCH;
- `adb shell id -u` должен вернуть root UID 0;
- должен быть найден запускаемый `tcpdump`;
- preflight сохраняет фактический tcpdump path/version.

Capture command:

```text
adb -s <serial> exec-out <tcpdump> -i any -p -s 0 -U -w -
```

Artifacts:

- `01_raw/network/traffic.pcap` — binary raw packet capture;
- `01_raw/network/tcpdump.stderr.txt` — diagnostics;
- `02_normalized/network.json` — backend/preflight, command, PID, timestamps, return code, PCAP format и размеры.

Требования:

- collector стартует в session state `starting`, до запуска исследуемого package;
- packet capture идёт со всех интерфейсов (`-i any`);
- snaplen не ограничивается (`-s 0`);
- `-U` используется для быстрой передачи packet blocks на host;
- PCAP поток пишется напрямую на Windows через `adb exec-out`;
- STOP сначала пытается послать SIGINT однозначно найденному remote PID `tcpdump`;
- затем допустим host terminate/kill fallback после grace period;
- forced kill не инвалидирует PCAP, если файл успешно проходит валидацию;
- итоговый файл проверяется как classic PCAP по magic number и версии 2.4;
- неожиданное завершение процесса или невалидный PCAP переводят collector в `failed` и session degraded;
- raw bytes не удаляются при ошибке.

Ограничение v0.1: этот backend предназначен для AVD-RESEARCH. AVD-PLAY и Physical Device требуют других network capture backends и не должны зависеть от root/tcpdump.

### 5.4 Device/system metadata

Collector сохраняет исходные Android-ответы в `01_raw/device/`:

- `getprop.txt` — полный `getprop`;
- `package.txt` — полный `dumpsys package <package>`;
- `package-paths.txt` — результат `pm path <package>`;
- `system.txt` — дополнительные system snapshot-команды;
- `clock.txt` — host/target clock markers вокруг snapshot.

Производный `02_normalized/target.json` содержит минимум:

- ADB serial;
- Android release;
- SDK level;
- manufacturer;
- model;
- ABI;
- build fingerprint;
- package name;
- package version name/version code, если доступны;
- first/last install timestamps, если доступны;
- package paths;
- host UTC timestamp начала и окончания metadata capture;
- target UTC timestamp начала и окончания metadata capture;
- сведения о collector backend;
- ошибки необязательных system-команд.

`target.json` не заменяет raw-файлы и может быть восстановлен из них. Обязательные metadata-команды должны завершиться успешно; сбой дополнительной system-команды фиксируется, но не делает весь snapshot невалидным.

## 6. Session Manager contract

Session Manager создаёт runtime layout и атомарно поддерживает `00_manifest/session.json`.

State machine:

```text
created
  ↓
preflight
  ↓
ready
  ↓
starting
  ↓
active
  ↓
stopping
  ├─ complete
  ├─ partial
  └─ failed
```

Из любого нетерминального состояния допустим переход в `failed` при fatal error.

Non-fatal collector failure во время `active` не должен останавливать другие collectors. В этом случае:

```text
status = active
degraded = true
```

При STOP:

```text
degraded = false → complete
degraded = true  → partial
```

Каждый переход и ошибка фиксируются с UTC timestamp. Manifest должен переживать повторную загрузку после рестарта процесса.

## 7. Порядок запуска

```text
preflight
  ↓
create/maintain session manifest
  ↓
start logcat
  ↓
start screen recorder
  ↓
start raw network capture
  ↓
record START synchronization marker
  ↓
launch target package
  ↓
ACTIVE SESSION
```

Все обязательные collectors стартуют до запуска исследуемого package.

## 8. Завершение

По STOP:

1. фиксируется STOP timestamp;
2. collectors завершаются штатно;
3. оставшиеся процессы принудительно завершаются только после grace period;
4. проверяются обязательные raw-файлы;
5. формируется окончательный manifest;
6. вычисляется SHA-256 evidence;
7. создаётся Research ZIP;
8. ZIP проверяется на читаемость и обязательные entries.

Raw-файлы не модифицируются ради построения отчётов.

## 9. Failure model

### Preflight failure
Сессия не переводится в ACTIVE, package автоматически не запускается.

### Collector startup failure
Если обязательный collector не запустился, активное исследование не начинается.

### Failure во время ACTIVE
Non-fatal failure выставляет `degraded=true`; ACTIVE capture остальных sources продолжается. После STOP итоговый статус — `partial`.

### Fatal failure
Сессия переводится в `failed`; уже записанные evidence не удаляются.

### Export failure
Runtime session сохраняется полностью и может быть повторно упакована без повторения исследования.

## 10. Runtime layout

```text
<session-id>/
├── 00_manifest/
│   ├── session.json
│   └── checksums.sha256
├── 01_raw/
│   ├── logcat/logcat.txt
│   ├── screen/screen-0001.mp4
│   ├── network/traffic.pcap
│   └── device/
│       ├── getprop.txt
│       └── package.txt
└── 02_normalized/
    └── target.json
```

Фактический сетевой формат может быть `.pcap` или `.pcapng`; manifest содержит реальный путь и формат.

## 11. Research ZIP contract

ZIP повторяет session layout и обязан содержать:

- финальный `session.json`;
- SHA-256 raw evidence;
- версию Mobile Research;
- статус сессии;
- перечень collectors и фактические результаты;
- диагностические ошибки для `partial` / `failed`.

Research ZIP не зависит от исходного расположения runtime session на Windows.

## 12. Manifest: минимальная семантика

- `schema_version`;
- `session_id`;
- `mobile_research_version`;
- `status`;
- `degraded`;
- `host`;
- `target`;
- `package`;
- `timestamps`;
- `collectors`;
- `artifacts`;
- `errors`;
- `state_history`.

## 13. Acceptance criteria v0.1

1. Windows видит AVD-RESEARCH через ADB.
2. Mobile Research подтверждает выбранный package.
3. Все обязательные collectors стартуют.
4. Mobile Research запускает package.
5. Пользователь выполняет действия.
6. STOP завершает collectors без потери уже собранных данных.
7. Создаётся Research ZIP.
8. В ZIP есть непустые logcat, screen recording, raw network capture и device metadata.
9. SHA-256 проверяется.
10. ZIP проходит повторную проверку.
11. Ошибка collector во время ACTIVE приводит к `partial` после STOP, а не к удалению сессии.

## 14. Не входит в v0.1

- GUI;
- MITM и TLS decryption;
- Android Research Agent;
- runtime instrumentation;
- маскировка исследовательской среды;
- статический APK-анализ;
- автоматическое управление Google Play;
- AVD-PLAY acceptance;
- Physical Device acceptance;
- автоматическая интерпретация действий пользователя;
- timeline inference;
- HTTP/WebSocket/gRPC decoding.
