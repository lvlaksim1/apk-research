# v0.22 — Packet ↔ Action Evidence

## Purpose

Close the packet-to-Timeline navigation gap using only evidence already present in a Research ZIP.

## Source evidence

- `01_raw/network/traffic.pcap` — authoritative raw network capture;
- `02_normalized/network-flows.json` — canonical normalized flow identity;
- `02_normalized/research-timeline.json` — exported action correlation windows.

No new raw or normalized artifact is created.

## Matching rule

For a selected flow, Packet Inspector loads the archived Timeline and considers only actions that already reference the same `flow_id`.

For each such action, the existing exported target-time window is reconstructed from:
- `target_started_utc_estimate`;
- `target_finished_utc_estimate`;
- `window.actual_after_seconds`.

A packet is linked to the action only when its PCAP target timestamp is inside that exact window.

## Evidence semantics

Every emitted relation contains:
- action ID and action type;
- exact start/end of the reused Timeline window;
- Timeline causal-confidence label;
- `attribution=temporal-only`;
- `causal_claim=false`.

The confidence label describes the existing Timeline correlation quality. It is not a probability that the action caused the packet.

## GUI

The Packets tab exposes:
- an Action-window column;
- search by action ID/label;
- temporal-window provenance in packet details;
- direct Packet → Timeline navigation.

## Failure/degradation behavior

If `research-timeline.json` is missing or invalid, packet inspection still works over raw PCAP. The report marks Timeline status and emits no packet/action links rather than guessing.

## Unchanged boundaries

- raw PCAP remains authoritative;
- encrypted payload is not represented as plaintext;
- capture collectors and Research ZIP schemas are unchanged;
- hidden Emulator → gRPC/MMAP → AndroidView remains the live display path;
- v0.10.5 clean-launch sequencing is unchanged;
- Audio Evidence and Virtual Display remain out of scope.
