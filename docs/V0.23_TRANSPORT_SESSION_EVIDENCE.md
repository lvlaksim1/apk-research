# v0.23 — Transport Session Evidence

## Purpose

Add conservative TCP session interpretation to Raw / Packet Inspector using only header evidence already present in the authoritative Research ZIP PCAP.

## Source evidence

- `01_raw/network/traffic.pcap` — authoritative packet capture;
- `02_normalized/network-flows.json` — canonical selected flow identity.

No new raw or normalized artifact is created.

## Per-packet TCP evidence

For valid TCP headers the inspector exposes:
- sequence number;
- acknowledgment number;
- TCP flags;
- TCP header length;
- receive window;
- payload length.

Invalid/truncated headers remain explicit rather than being guessed.

## Session summary

For a selected TCP flow:
- a complete handshake requires observed SYN → SYN/ACK → ACK in capture order;
- FIN and RST are reported only from observed packets;
- supporting packet IDs are retained;
- non-TCP flows are marked not applicable.

## Evidence semantics

The summary is capture-bounded. If lifecycle packets are absent, the result is `partial-or-not-observed-in-capture` or `not-observed-in-capture`.

These states mean only that apk-research did not observe the packets in this capture. They are not proof that the corresponding event did not occur.

No TCP application stream reconstruction, missing-packet synthesis or plaintext inference is introduced.

## GUI

The Packets tab exposes transport-session status in the flow summary, transport metadata in packet details and transport terms in free-text search.

## Unchanged boundaries

- raw PCAP remains authoritative;
- Packet ↔ Action remains `temporal-only`, `causal_claim=false`;
- Research ZIP schemas and collectors are unchanged;
- hidden Emulator → gRPC/MMAP → AndroidView remains the live display path;
- v0.10.5 clean-launch sequencing is unchanged;
- canonical screenrecord remains authoritative;
- Audio Evidence and Virtual Display remain out of scope.
