# v0.16.0 — QUIC / HTTP/3 Network Intelligence

## Scope

v0.16.0 extends post-capture network analysis for modern QUIC traffic while preserving the validated runtime and raw-evidence pipeline.

Unchanged runtime boundary:

`hidden Emulator → gRPC → MMAP → AndroidView`

Unchanged raw network source of truth:

`01_raw/network/traffic.pcap`

The release does not alter clean-launch sequencing, emulator startup, input transport, socket attribution sampling or tcpdump capture.

## QUIC evidence

The PCAP parser now recognizes QUIC long-header packets on UDP/443 and records:

- QUIC version;
- long-header packet type;
- whether a client Initial packet was successfully decrypted;
- TLS ClientHello SNI carried in QUIC CRYPTO frames;
- ALPN values;
- derived application protocol label `HTTP/3` when ALPN is `h3` or an `h3-*` draft identifier.

Supported Initial cryptography:

- QUIC v1 — RFC 9000 / RFC 9001;
- QUIC v2 — RFC 9369.

QUIC Initial packet protection does not provide confidentiality against an observer because Initial keys are derived from public connection information. apk-research derives only those public Initial secrets. It does not perform MITM, install a CA, modify the researched app or decrypt QUIC 1-RTT application data.

## CRYPTO reassembly

Client Initial CRYPTO fragments are reassembled across packets sharing the same version and Destination Connection ID. This allows ClientHello metadata to be recovered when the handshake is split across multiple Initial packets.

Reassembly is evidence-preserving:

- packet bytes remain unchanged in raw PCAP;
- normalized values are derived metadata;
- no hostname is inferred from an unrelated DNS answer;
- SNI is reported only when it is actually parsed from a successfully decrypted QUIC Initial ClientHello.

## Normalized schemas

`02_normalized/network-flows.json` is schema `0.3`.

A normalized flow may now contain:

- `quic_versions`;
- `quic_packet_types`;
- `quic_alpn`;
- `application_protocols`;
- `quic_detected_packet_count`;
- `quic_initial_decrypted_packet_count`.

The summary adds:

- `quic_flow_count`;
- `http3_flow_count`;
- `quic_detected_packet_count`;
- `quic_initial_decrypted_packet_count`;
- `quic_versions`.

Research Timeline is schema `0.5` and exposes the same QUIC/application-protocol evidence in action correlation samples and global summary counters.

## Network Analyzer

The Network Analyzer keeps transport and application protocol separate. Examples:

- `TCP` transport with conventional TLS/HTTPS evidence;
- `UDP • QUIC`;
- `UDP • HTTP/3`.

Flow details show QUIC version, ALPN and the count of successfully decrypted Initial packets. QUIC SNI participates in the existing host grouping because it is TLS ClientHello SNI with explicit QUIC provenance in the normalized flow.

## Evidence boundary

v0.16.0 does not claim that all UDP/443 is QUIC. QUIC is marked only when a recognizable QUIC long header is observed.

Short-header-only traffic cannot be independently identified as QUIC without earlier connection context. Encrypted 1-RTT payloads remain opaque. The raw PCAP remains the source of truth for future re-analysis.
