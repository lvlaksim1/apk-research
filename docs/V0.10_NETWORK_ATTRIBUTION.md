# Mobile Research v0.10 — Package-aware Network Attribution

## Цель

Отделить трафик исследуемого APK от системного и фонового Android traffic не только по времени, а по наблюдаемой ownership-цепочке `package → UID → PID → socket inode → 5-tuple → PCAP`.

## Evidence pipeline

1. `cmd package list packages -U` определяет UID исследуемого package и все packages, разделяющие этот UID.
2. Persistent sampler каждые 200 мс фиксирует target realtime, `/proc/net/tcp`, `tcp6`, `udp`, `udp6`, процессы target UID и их `/proc/<pid>/fd` socket inode.
3. Raw sampler stream сохраняется без интерпретации в `01_raw/network/socket-snapshots.txt`.
4. Normalizer строит `socket-attribution.jsonl` и summary `socket-attribution.json`.
5. Timeline/flow analyzer связывает PCAP packets с socket observations и сохраняет whole-session `network-flows.json`.

## Confidence

- `EXACT`: inode + exact 5-tuple + packet внутри непосредственно наблюдавшегося lifetime сокета + однозначный owner. Owner считается однозначным при unique package UID либо при shared UID с прямой связью target-package process/PID → FD → inode.
- `HIGH`: сильное socket evidence, но packet попал только в sampling margin либо используется менее точный endpoint evidence.
- `MEDIUM`: более слабое local-endpoint/local-port evidence.
- `UNKNOWN`: достаточной ownership-связи нет; в частности, shared UID без прямой target-process → socket inode связи не приписывается исследуемому package.

Отсутствие совпадения не означает отсутствие трафика приложения: короткоживущий сокет может существовать между snapshots. Такой packet остаётся `UNKNOWN`.

## Отдельность причинности

`owner.confidence` отвечает только на вопрос «чей это flow?». Поле Research Timeline `causal_claim` отвечает на другой вопрос — «доказано ли, что действие пользователя вызвало flow?». v0.10.0 не смешивает эти утверждения: action correlation остаётся `temporal-only` и `causal_claim=false`.

## Research ZIP

- `01_raw/network/traffic.pcap` — первичный packet evidence.
- `01_raw/network/socket-snapshots.txt` — первичный ownership snapshot stream.
- `02_normalized/socket-attribution.jsonl` — нормализованные snapshots.
- `02_normalized/socket-attribution.json` — package/UID/sampling summary.
- `02_normalized/network-flows.json` — whole-session flow inventory.
- `02_normalized/research-timeline.json` schema 0.3 — action correlations и owner evidence.

## Ограничения v0.10.0

Sampling не является kernel event stream: он может пропустить крайне короткий socket lifetime. Shared UID не позволяет присвоить owner одному package только на основании UID; `EXACT` при shared UID допустим лишь при прямой наблюдаемой связи target-package process/PID → FD → socket inode. Без неё ownership остаётся `UNKNOWN`. Эти ограничения отражаются в confidence/ambiguity, а не скрываются эвристикой.
