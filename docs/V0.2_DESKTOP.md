# Mobile Research v0.2 — Desktop Application Contract

## Цель

v0.2 превращает доказанное ядро v0.1.0 в самостоятельное Windows-приложение. Командная строка, Python, Android Studio, ручной ADB и ручное создание AVD не являются частью штатного пользовательского сценария.

## Пользовательский сценарий

Установить MobileResearchSetup.exe → запустить Mobile Research → выбрать APK → программа сама готовит Android → НАЧАТЬ ИССЛЕДОВАНИЕ → работать с Android внутри окна → ЗАВЕРШИТЬ И СОХРАНИТЬ → Research ZIP.

## Self-contained Windows distribution

Python runtime и Qt входят в приложение. Пользователь не устанавливает Python, pip или venv.

## Managed Android components

Android Studio не требуется. Mobile Research загружает официальные Android packages из Google repository metadata в %LOCALAPPDATA%\MobileResearch\components.

Baseline: platform-tools/ADB, stable Android Emulator из Google repository channel-0, build-tools 35.0.0/aapt2, Android 15 API 35 AOSP default x86_64 image и private AVD mobile_research_api35.

При первом использовании GUI получает одноразовое согласие с Android SDK License Agreement. После этого download, checksum verification, extraction и configuration выполняются программой.

## Embedded Android

Android Emulator запускается headless. Отдельное окно emulator не показывается. Mobile Research отображает framebuffer внутри GUI через ADB screencap и преобразует mouse/keyboard input в Android input tap/swipe/text/keyevent.

## Virtualization

Mobile Research проверяет acceleration. При отсутствии Windows features программа best-effort включает HypervisorPlatform и VirtualMachinePlatform через UAC/DISM. Если Windows требует reboot, приложение сообщает об этом.

## Research core

Гарантии v0.1.0 сохраняются: immutable raw evidence, metadata, logcat, screen recording, mandatory raw PCAP, complete/partial/failed, SHA-256 Research ZIP и semantic audit. GUI вызывает core classes напрямую и не запускает CLI subprocess.

## Build gate

Каждый релевантный commit запускает Windows CI, real AVD Research Acceptance и Desktop Build.

Desktop Build проверяет unit tests, live Android catalog, standalone EXE/GUI, Inno Setup, установленное приложение и clean-Windows provisioning managed Android: download, checksum verification, extraction, tool versions и private AVD creation.

GitHub-hosted Windows runner не используется как доказательство пользовательского Android boot: nested virtualization на hosted runner не является стабильным release-контрактом. Linux/KVM AVD Research Acceptance по-прежнему проверяет research core на реальном Android.

Дополнительно следующий stable Windows release требует `Windows WHPX Acceptance` на выделенном Windows x64 hardware-capable self-hosted runner. Gate скачивает exact-SHA installer из Desktop Build, выполняет чистую установку, запускает именно установленный frozen MobileResearch.exe, требует provider `whpx` из `emulator -accel-check`, автоматически provision/boot private AVD и выполняет complete research session с verify + semantic audit Research ZIP.

Stable release публикуется только после успеха всех gates для одного exact commit SHA, включая Windows WHPX Acceptance.
