# Mobile Research — Desktop Application Contract

## Цель

Desktop-слой превращает Research Session Core в самостоятельное Windows-приложение. Штатный пользовательский сценарий не требует Python, PowerShell, Android Studio, ручного ADB или ручного создания AVD.

## Пользовательский сценарий

Установить `MobileResearchSetup.exe` → запустить Mobile Research → выбрать APK → программа сама готовит Android → работать с Android внутри окна → НАЧАТЬ ИССЛЕДОВАНИЕ → ЗАВЕРШИТЬ И СОХРАНИТЬ → Research ZIP.

## Self-contained Windows distribution

Python runtime и Qt входят в приложение. Пользователь не устанавливает Python, pip или venv.

## Managed Android components

Android Studio не требуется. Mobile Research загружает официальные Android packages из Google repository metadata в `%LOCALAPPDATA%\MobileResearch\components`.

Baseline: platform-tools/ADB, stable Android Emulator из Google repository channel-0, build-tools 35.0.0/aapt2, Android 15 API 35 AOSP default x86_64 image и private AVD `mobile_research_api35`.

## Embedded Android — единственный Windows contract

Штатный Windows runtime имеет ровно один interactive path:

```text
emulator -qt-hide-window
        ↓
Emulator gRPC
        ↓
streamScreenshot + MMAP
        ↓
AndroidView
```

Mouse/keyboard input передаётся только через persistent gRPC `streamInputEvent`. Pointer drag — настоящий DOWN → MOVE → UP lifecycle.

Не существует пользовательского fallback на DWM, visible standalone Emulator, gRPC byte frames, ADB screencap или ADB input. Если обязательный transport недоступен, подготовка Android завершается ошибкой с диагностикой.

На Linux/KVM автоматический acceptance запускает Emulator с `-no-window`, но framebuffer/input transport остаётся тем же обязательным gRPC/MMAP. Это CI host mode, а не альтернативный Windows UX.

## Startup и recovery

Windows использует primary GPU backend для того же hidden gRPC/MMAP path; автоматического перехода на другую display architecture нет.

Если Emulator process жив, но Android не достигает `sys.boot_completed=1`, это guest/AVD boot stall. Допускается ровно одно восстановление через официальный `-wipe-data` с тем же required runtime.

Startup cleanup может завершить только stale процессы private AVD Mobile Research и удалить его stale locks после исчезновения процессов. Это recovery штатной архитектуры.

Если clean AVD снова stalls либо обязательный gRPC/MMAP transport не работает, Mobile Research останавливает подготовку и сообщает ошибку.

## Virtualization

Mobile Research проверяет Android Emulator acceleration. На Windows предпочтителен WHPX; уже установленный usable AEHD/GVM остаётся поддерживаемым virtualization provider. Это не меняет display/input architecture.

Если usable hypervisor отсутствует, Mobile Research одним UAC-запросом включает Windows Hypervisor Platform (`HypervisorPlatform`) и выставляет `hypervisorlaunchtype=Auto`. `VirtualMachinePlatform` автоматически не включается. Если требуется reboot, приложение сообщает об этом явно.

## Research core

Гарантии v0.1.0 сохраняются: immutable raw evidence, metadata, logcat, screen recording, mandatory raw PCAP, complete/partial/failed semantics, SHA-256 Research ZIP и semantic audit. ADB остаётся research/control transport для collectors и package/device operations, но больше не является interactive display/input fallback.

В режиме clean research boundary задаётся после preflight: collectors сначала armed, затем package force-stop'ится, Mobile Research подтверждает отсутствие package process и только после этого запускает launcher activity. Full verbose Package Manager dump является дополнительным metadata evidence и не определяет сам по себе статус complete/partial.

Screen timing хранит отдельно wall-clock interval жизни recorder process и Winscope frame presentation timestamps. Raw MP4 не переписывается для искусственного растягивания idle intervals.

## Build and release gates

Каждый релевантный commit запускает `CI`, `AVD Research Acceptance` и `Desktop Build`. Stable Release ждёт их success для exact SHA и публикует проверенный installer. `Windows WHPX Acceptance` остаётся отдельной advisory hardware-проверкой, пока dedicated runner не гарантирован.

Desktop Build обязательно выполняет standalone GUI open/close smoke-test.

## Stable runtime baseline

Реальным пользовательским тестом v0.8.2 подтверждены отсутствие вспышек standalone Emulator, правильная ориентация MMAP framebuffer, совпадение display/touch geometry, плавный streaming swipe и нормальный отклик. v0.8.9 сохраняет именно этот механизм как единственный поддерживаемый пользовательский runtime; изменения релиза относятся только к research evidence sequencing/metadata/timing.
