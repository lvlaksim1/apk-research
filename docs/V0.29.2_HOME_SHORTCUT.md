# v0.29.2 — Automatic Home Shortcut

## Goal

Make the emulator behave as expected after installing an APK/XAPK: the application must have a visible launch shortcut on the managed Android home screen without a separate Home button.

## Managed Launcher contract

The managed Android 15 AVD was probed before implementation. It uses `com.android.launcher3`, and its workspace model is exposed through:

`content://com.android.launcher3.settings/favorites`

The launcher database name also exposes the active grid size, for example `launcher_4_by_4.db`.

## Installation flow

After package installation and optional OBB transfer:

1. Resolve the package MAIN/LAUNCHER component.
2. Resolve the Android HOME component.
3. Require the managed Launcher3 package.
4. Query existing launcher favorites.
5. If the package already exists on the workspace, do not create a duplicate.
6. Read the Launcher3 grid size and select the first free cell.
7. Insert a normal application item (`itemType=0`, `container=-100`) with the package launch intent.
8. Re-query the provider and verify the package entry.
9. Reload Launcher3 and return to the home screen.

## Failure behavior

If the installed package has no launcher activity, or Launcher3 does not confirm the inserted entry, apk-research reports a concrete error. It does not claim that a shortcut exists when it cannot be verified.

## Tests

- Pure parser/free-cell/duplicate tests for Launcher3 favorites.
- Application-label parsing test.
- GUI smoke test confirms the removed Home button is no longer part of the contract.
- Real AVD XAPK acceptance confirms the installed package has a Launcher3 shortcut.

## Boundaries

No changes to ABI selection, updater, research collectors, RAW PCAP, timeline/network evidence or dual-source screen semantics.

## UI confirmation

There is no user-facing Home action in v0.29.2; returning to the Android home screen happens only as the final internal step of a successful installation.
