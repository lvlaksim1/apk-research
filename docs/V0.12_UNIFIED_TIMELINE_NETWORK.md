# apk-research v0.12 — Unified Timeline / Network model

## Objective

There is now one network connection identity throughout apk-research:

```
RAW PCAP packet
    ↓
canonical bidirectional TCP/UDP 5-tuple
    ↓
flow_id in network-flows.json
    ↓
Timeline correlation / event
    ↓
Network Analyzer row
```

No second directional-flow identity is created by Timeline.

## Timeline schema 0.4

Timeline network events have:

```json
{
  "kind": "network_flow",
  "name": "network_flow_started",
  "flow_id": "flow-000001"
}
```

A user action correlation has:

```json
{
  "network": {
    "flow_ids": ["flow-000001"],
    "new_flow_ids": ["flow-000001"]
  },
  "causal_claim": false,
  "attribution": "temporal-only"
}
```

The corresponding normalized flow contains:

```json
{
  "flow_id": "flow-000001",
  "correlated_action_ids": ["action-000001"]
}
```

## Navigation

Timeline → Network Analyzer:
double-click a row that contains one or more `flow_ids`.

Network Analyzer → Timeline:
double-click a flow with `correlated_action_ids`.

Navigation does not mutate the Research ZIP or evidence.

## Coverage accounting

Flow summary distinguishes:

- `source_packet_count`;
- `flow_packet_count`;
- `non_tcp_udp_packet_count`;
- `non_tcp_udp_bytes`;
- `non_tcp_udp_protocol_counts`;
- `unresolved_transport_packet_count`.

This makes the TCP/UDP-normalization boundary explicit without discarding non-flow packets from RAW PCAP.
