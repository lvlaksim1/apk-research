# v0.18 — Raw / Packet Inspector

## Purpose

Raw / Packet Inspector resolves a normalized network flow to the concrete packet records that form it in the original Research ZIP PCAP.

The user path becomes:

`Action → Host → Flow → Process/Socket → Packet → Raw PCAP`

## Source of truth

The inspector reads:

- `02_normalized/network-flows.json` for flow identity;
- `01_raw/network/traffic.pcap` for packet bytes.

It does not create a replacement packet artifact. Raw PCAP remains authoritative.

## Packet identity and locator

A displayed packet preserves:

- global PCAP packet index;
- target UTC timestamp;
- capture/derived direction;
- protocol and source/destination endpoints;
- captured and original lengths;
- PCAP record byte offset;
- PCAP frame byte offset.

The offsets are logical offsets in the uncompressed original PCAP object stored in the Research ZIP.

## Flow matching

Packet selection uses the same direction-independent canonical TCP/UDP endpoint key used by the normalized flow inventory. Inbound and outbound packets therefore resolve to the same flow.

## Raw preview

The GUI shows only a bounded raw-frame hex preview. The complete packet remains in the PCAP and is reachable through its locator.

Protocol metadata may expose evidence already recoverable from bytes, such as DNS query names, TLS ClientHello SNI and supported QUIC Initial metadata. Encrypted application data is not represented as plaintext.

## Compatibility

v0.18 is post-capture/presentation-only. It does not change:

- collectors;
- Research ZIP schemas;
- Android runtime;
- Emulator gRPC/MMAP display/input;
- v0.10.5 clean-launch sequencing;
- Action ↔ Flow `temporal-only` semantics.
