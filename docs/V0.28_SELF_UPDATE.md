# v0.28 — Direct GitHub Self-Update

## Цель

Дать пользователю штатный путь обновления apk-research без ручного поиска установщика: проверка новой версии и запуск обновления выполняются из раздела «Настройки», а источником является последний стабильный GitHub Release проекта.

## Проверка версии

Сетевой запрос выполняется только после нажатия «Проверить обновления». Фоновое периодическое опрашивание GitHub не используется.

Программа читает публичный `releases/latest` репозитория `lvlaksim1/apk-research` и принимает релиз только если:
- он не draft и не prerelease;
- tag имеет строгую форму `vX.Y.Z` / `X.Y.Z`;
- версия строго новее установленной;
- присутствует точный `apk-research-setup_vX.Y.Z.exe`;
- присутствует `SHA256SUMS.txt`;
- оба download URL относятся к GitHub Release этого репозитория.

Если новой версии нет, кнопка обновления остаётся скрытой.

## Скачивание и проверка

При нажатии «Обновить»:
1. скачивается `SHA256SUMS.txt`;
2. скачивается установщик в отдельный временный каталог;
3. SHA-256 вычисляется локально во время загрузки;
4. проверяется размер установщика из release metadata;
5. вычисленный SHA-256 сравнивается со строкой точного имени установщика в `SHA256SUMS.txt`.

Любое несовпадение останавливает процесс до запуска файла.

## Установка

Работающий exe не перезаписывает себя. После успешной проверки программа создаёт отдельный локальный процесс обновления, который:
1. ждёт завершения текущего PID apk-research;
2. запускает Inno Setup в тихом режиме;
3. указывает тот же каталог установки, из которого запущена программа;
4. ждёт успешного кода завершения;
5. снова запускает установленный `apk-research.exe`.

Обновление нельзя запускать во время исследования или другой управляемой операции.

## Границы

v0.28 не меняет:
- Android runtime;
- APK/XAPK intake;
- collectors;
- Research ZIP;
- RAW PCAP;
- network attribution;
- Timeline/Packet/Protocol/Investigator semantics;
- dual-source screen model.

## Проверка

Обязательны:
- тест сравнения версий;
- тест разбора `releases/latest`;
- тест выбора точных release assets;
- положительная и отрицательная проверка SHA-256;
- тест Windows handoff script;
- GUI smoke test наличия кнопок;
- полный CI;
- реальная AVD acceptance;
- Windows standalone/GUI/installer acceptance;
- clean-Windows provisioning.
